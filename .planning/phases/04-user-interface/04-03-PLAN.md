## Implementation

### Runtime Verification Procedure

**Pitfall 2 enforcement** — FakeX providers test dispatch logic only. This phase is the ONLY verification that catches real ACL/permission failures.

1. **Build self-contained deployment**:
   ```bash
   dotnet publish src/Akari.App/Akari.App.csproj -c Release -r win-x64 --self-contained true
   ```

2. **Launch elevated**: Run `Akari.App.exe` from the publish output directory with "Run as administrator"

3. **Verify each tweak category end-to-end**:

| Tweak ID | Category | Verify Via | Expected Log Entry |
|----------|----------|------------|-------------------|
| REG-01 | Registry | regedit → HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\GameList\GameMode = 1 | "Tweak REG-01 applied successfully" |
| REG-02 | Registry | regedit → HwSchMode = 2 | "Tweak REG-02 applied successfully" |
| REG-04 | Registry | regedit → Win32PrioritySeparation = 26 | "Tweak REG-04 applied successfully" |
| REG-07 | Registry | regedit → HKCU\Control Panel\Desktop\MouseSpeed = 0 | "Tweak REG-07 applied successfully" |
| SVC-01 | Service | services.msc → Xbox services stopped + disabled | "Tweak SVC-01 applied successfully" |
| SVC-02 | Service | services.msc + regedit → GameDVR/GameBar disabled | "Tweak SVC-02 applied successfully" |
| PROC-01 | Process | Task Manager → game process priority = High | "Tweak PROC-01 applied successfully" |
| PWR-01 | Power | powercfg /list → Ultimate Performance active | "Tweak PWR-01 applied successfully" |
| MEM-01 | Memory | Get-MMAgent → MemoryCompression = False | "Tweak MEM-01 applied successfully" |

4. **Log file check** — Open `%LOCALAPPDATA%\Akari\App\logs\app-YYYY-MM-DD.log`:
   - NO `UnauthorizedAccessException` entries
   - NO error-level log entries for any tweak application
   - Each "Tweak {id} applied successfully" entry present

5. **Revert verification** — Toggle each tweak off, verify:
   - Registry values revert to expected defaults
   - Services return to original state
   - Power plan returns to balanced
   - Memory compression re-enabled
   - No errors in log

6. **Batch apply verification** — Select all tweaks → "Apply Selected" → verify progress indicator reaches 100%, all tweaks show "Applied" state, no errors in log

### Clean Install Validation
1. Copy publish output to a clean Windows 11 machine (no .NET runtime pre-installed)
2. Verify app launches without .NET desktop runtime installed
3. Verify all tweaks work end-to-end

### Final Test Suite
- `dotnet test src/Akari.Engine.Tests/` — 60/60 pass (no regressions)
- `dotnet build src/Akari.ToolV2.sln -c Release` — 0 errors (except 3 pre-existing CS1574)

## Tests
No automated tests for this wave — all verification is runtime + elevated launch + log check (Pitfall 2). The existing 60 unit tests serve as regression protection.

## Risks
- **Runtime-only failures**: Only discoverable via elevated launch — FakeX providers will pass even with broken ACL handling
- **Power plan availability**: Ultimate Performance may not be available on all hardware — PWR-02 fallback must be exercised
- **Service state**: Some Xbox services may not exist on all Windows SKUs — must handle gracefully
- **Process priority**: PROC-01 requires a running game process — will need to test with a dummy process

## Success Criteria
- [ ] End-to-end: user applies all tweak categories from the UI and each is verified applied in the actual system
- [ ] Log file at `%LOCALAPPDATA%\Akari\App\logs\app-YYYY-MM-DD.log` contains no `UnauthorizedAccessException`
- [ ] Revert works for every tweak type — original system state restored
- [ ] Batch apply with progress reaches 100% — all tweaks applied successfully
- [ ] Self-contained win-x64 deployment builds successfully
- [ ] Clean install validation — app runs without .NET runtime pre-installed
- [ ] `dotnet test` — 60/60 tests still pass
